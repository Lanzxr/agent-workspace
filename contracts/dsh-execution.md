# DSH 执行契约

## 目的

把 DSH 固定为内部执行层。DSH 接收经过后端校验的执行请求，在指定 Agent Workspace 中运行工具，并返回可追踪的结果。

## 执行请求

执行请求至少包含：

- `execution_id`
- `agent_id`
- `workspace_id`
- `plan_step_id`
- 工具名称和结构化参数
- 工作目录
- 环境变量允许列表
- 超时时间和资源限制
- 网络和文件访问策略
- 关联审批和策略版本

## 执行结果

结果至少包含：

- `execution_id`
- `status`
- 开始和结束时间
- 退出码或错误类别
- 脱敏日志引用
- 成果文件引用
- 使用的工具和运行环境版本

## 边界

- DSH 不决定业务权限和群聊发布。
- DSH 不直接写入任务最终状态。
- DSH 不访问 Docker Socket、宿主机根目录或未授权生产密钥。
- 每一次执行都绑定一个 Workspace 和一个可审计的执行请求。
